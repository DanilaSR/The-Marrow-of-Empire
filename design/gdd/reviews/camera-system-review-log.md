# Camera System — Review Log

## Review — 2026-08-09 — Verdict: MAJOR REVISION NEEDED (revised same session)
Scope signal: L
Specialists: game-designer, systems-designer, lead-programmer, qa-lead, ux-designer, creative-director (senior)
Blocking items: 8 (pre-revision) → 5 (post-revision) | Recommended: 8 → 3

**Summary**: Five independent adversarial reviews converged on three core failures. (1) The zoom model was geometrically undefined — orthographic cameras zoom by frustum size, not camera height, and the frustum extents were never specified. (2) The follow math was unimplementable — "lerp at 5 units/sec" is not a valid specification; two implementations would be faithful to the text with opposite feels. (3) The conversation/journal UX locked the camera during the game's primary activities — forced Close zoom with disabled pan during potentially 10-minute AI conversations, and a frozen journal in an investigation game. Additional findings: state machine had no priority rules, boundary enforcement had an undeclared dependency on the Alpha-tier Map System, the audio listener claim was false (Kaiju has no 3D audio API), occlusion had no strategy, and 0 of 8 acceptance criteria were testable. The lead-programmer confirmed Kaiju supports orthographic natively via `NewStandardCameraOrthographic` — the engine premise survived.

**Revision (2026-08-09, same session)**: ~80% of findings resolved in the initial revision round. Zoom model corrected to orthographic half-height (O=4/10/20u) with derived camera position. Follow math pinned to exponential ease with explicit formula. Conversation and journal states grant full player pan/zoom control. State machine formalized with priority order and transition matrix. Shake made screen-space-based and zoom-independent with MVP accessibility toggle. Occlusion policy added (CR-8). AC suite rewritten with methodology. Audio dependency honestly reframed as engine backlog.

**Second revision (2026-08-09, same session — this review)**: 5 remaining items resolved. Zoom interaction model changed to free wheel + 3 snap detents + strict-levels toggle. Party membership defined via `pc_controlled` EF tag query for MVP. Shake space specified as camera-local vector offsetting both position AND lookAt. Degenerate focus fallback defined (empty set → last valid focus or region entry point). Boundary dependency back-reference added (Asset & Scene Pipeline row, bidirectional).

Prior verdict resolved: Yes — MAJOR REVISION NEEDED → revised (same session) → NEEDS REVISION (5 items remaining) → revised → pending re-review

## Review — 2026-08-09 — Verdict: MAJOR REVISION NEEDED (third round, revised same session)
Scope signal: XL
Specialists: game-designer, systems-designer, ux-designer, qa-lead, performance-analyst, lead-programmer, creative-director (senior synthesizer)
Blocking items: 11 → 0 (all resolved in revision) | Recommended: 4 (creative decisions, all resolved)

**Summary**: Third adversarial review converged on 10 findings independently confirmed by 2-4 specialists each. The GDD's direction and structural rulings from rounds 1-2 survived, but four categories of precision failure made it unimplementable: (1) the EF position-cache mechanism was unbuildable — no position-change event exists; a programmer following the text would build a stale-position camera; (2) CR-6 art padding math was wrong by ~50% — the 45°-rotated viewport AABB requires 53.4u padding at Far zoom (16:9), not 36u; (3) the state model was logically false — priority order violated by the doc's own transition matrix, one-deep stack broken by Transition always exiting to Exploration; (4) the shake AC asserted 1.5% peak displacement but the GDD's own formula (sine phase-0 + linear falloff) produces a sampled max of ~1.03%. Additional convergent findings: AC suite had 8 failing ACs and ~17 missing; conversation re-frame contradicted the "no world motion behind text" rule; occlusion had no budget and outline-through-geometry is not supported by Kaiju; zoom ACs described the old discrete-3-level design while rules described free wheel + detents; Strict Zoom Levels toggle was absent from Settings and all ACs; combat framing had a 32u quantization cliff; performance measurement methodology couldn't catch the failures it claimed to prevent.

**Revision (2026-08-09, same session)**: All 11 blockers resolved. EF contract rewritten to lifecycle-event membership + per-frame Transform reads. CR-6 padding recomputed to 53.4u (16:9) / 61.3u (21:9 worst case) with clamp on focus. State model redesigned: Manual as mode modifier, Journal as overlay, return stack depth 2, Transition restores pre-crossing state. Shake redefined as envelope amplitude with cosine waveform. Combat-end returns to Manual (no drift-back). Combat framing uses camera-axes, zooms from persisted level, hysteresis margin. Conversation re-frames defined (NPC change + 85% threshold + 300ms ease, inter-line gaps only). Occlusion extended to combatants with 3-fade cap + 30u distance cap + 0.3ms CPU budget; outlines gated on engine spike. AC suite: measurement protocol preamble, zoom ACs rewritten for free wheel + detents + Strict toggle, 8 failing ACs fixed, ~20 missing ACs added, stable IDs assigned (CAM-ZOOM-01, etc.). Four creative decisions resolved: minimal Cinematic state (CR-9, 2 ACs), zoom-to-cursor, save/load contract (position reset + zoom restore), outlines gated on engine spike + ADR. Cross-document corrections required in entity-framework.md and save-load-system.md — flagged for coordination pass.

Prior verdict resolved: Yes — MAJOR REVISION NEEDED (third round) → all 19 fixes applied → re-reviewed in lean mode → APPROVED
