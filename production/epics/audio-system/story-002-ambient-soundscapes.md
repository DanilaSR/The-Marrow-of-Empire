## Implementation Notes

*Derived from ADR-0007 Implementation Guidelines and GDD audio-system.md:*

1. **Light state → ambient mapping**: Define a mapping table (YAML config at `assets/audio/ambient/ambient_config.yaml`) from each light state to its ambient audio asset(s):
   - Dawn (04:00–07:00): birdsong, soft wind
   - Day (07:00–17:00): wind through trees, distant activity
   - Dusk (17:00–20:00): crickets, evening birds
   - Night (20:00–02:00): owls, distant howls
   - Deep Night (02:00–04:00): near-silence, sparse cricket
2. **Crossfade engine**: On light state transition event from EventBus (ADR-0011), start crossfade: ramp down current ambient gain from 1.0 → 0.0 over N seconds while simultaneously ramping up next ambient gain from 0.0 → 1.0. Use linear gain interpolation in the audio update loop.
3. **Transition timing**: Default crossfade duration is 5 seconds. Configurable per transition pair via the YAML config. The crossfade starts at the light-state boundary (e.g., 07:00 for Dawn→Day).
4. **Clock freeze behavior**: Subscribe to `GameClockPaused` and `GameClockResumed` events. On pause, stop ambient playback and record position. On resume, restart from recorded position (or begin new crossfade if light state changed during pause).
5. **Region blending**: Region ambience is a separate audio layer with its own gain. Triggered by entity proximity or region triggers. Gain = f(distance to region center). Region sounds layer on top of time-of-day ambient (both play simultaneously). Maximum 3 concurrent region layers.
6. **Data-driven config**: All ambient mappings, crossfade durations, and region definitions are in external YAML, never hardcoded. Follows ADR-0005's content-separation principle.
