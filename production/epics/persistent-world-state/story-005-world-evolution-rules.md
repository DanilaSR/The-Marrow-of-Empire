**ADR Governing Implementation**: ADR-0013: Persistent World State — Memory Log & Evolution Rules
**ADR Decision Summary**: World evolution rules are YAML-authored condition→event pairs evaluated once on region load (not continuously). Conditions support equality, comparison, AND/OR, `days_since(flag_name)`, and `has_flag(entity_id, flag_name)`. Rules fire in declaration order — no re-evaluation loop. If a rule modifies a flag read by an earlier rule in the same pass, a warning is logged (circular dependency detection).

**Engine**: Kaiju Engine 26.07.29.1-nightly (Go/Vulkan) | **Risk**: MEDIUM
**Engine Notes**: YAML parsing via Go's `gopkg.in/yaml.v3`. Rules are designer-authored data files at `assets/world_rules/{region_id}.yaml`. No Kaiju APIs — pure Go data processing. Evolution rules delegate to SubmitWorldEvent (Story 002) for actual state changes.

**Control Manifest Rules (Feature Layer)**:

- Guardrail: Evolution rules (20 rules): <1ms per region load — ADR-0013

## Acceptance Criteria

*From GDD `design/gdd/persistent-world-state.md`:*

- [ ] **AC-1**: GIVEN an entity with `world.ruin_cleared = true` and `world.ruin_cleared_at = [7 game days ago]`, WHEN the region is loaded, THEN the evolution rule `IF world.ruin_cleared AND days_since(world.ruin_cleared_at) > 7 THEN location_repopulated` fires and a new world event is submitted.
- [ ] **AC-2**: GIVEN multiple rules in declaration order, WHEN the region is loaded, THEN rules are evaluated in order. If rule 3 modifies a flag read by rule 1, rule 1 does NOT re-fire — evaluation runs once.
- [ ] **AC-3**: GIVEN a rule with a circular dependency (rule A sets flag F, rule B earlier in order reads flag F), WHEN evaluated, THEN a warning is logged about the circular dependency.
- [ ] **AC-4**: GIVEN a rule targeting a destroyed entity, WHEN the region is loaded, THEN the rule is skipped and a warning is logged.
- [ ] **AC-5**: GIVEN a YAML rule file with valid syntax, WHEN parsed, THEN rules are loaded into the rule set. Invalid syntax returns a parse error.

## Implementation Notes

*Derived from ADR-0013:*

- Rule file format per ADR-0013: `assets/world_rules/{region_id}.yaml` with a `rules:` list.
- Each rule: `name`, `condition` (expression string), `event` (type, target, details map).
- Condition parser: tokenize the expression string, evaluate against current world flags and game time.
- Supported operators: `==`, `!=`, `>`, `<`, `AND`, `OR`, `days_since(flag_name)`, `has_flag(entity_id, flag_name)`.
- `days_since(flag_name)`: reads the flag value (a timestamp), computes `current_game_time - flag_value`.
- `has_flag(entity_id, flag_name)`: queries the flag store for the given entity and flag.
- Evaluation: on `EvaluateRegion(regionID string, flags WorldFlagStore, gameTime float64)`, iterate rules in order. For each rule where condition evaluates to true: construct a WorldEvent from the rule's `event` block and call `SubmitWorldEvent`.
- Circular dependency detection: track which flags each rule reads vs writes. If rule N writes a flag that an earlier rule (1..N-1) reads, log a warning.
- Exported: `EvolutionRule`, `RuleSet`, `ParseRules(yamlBytes []byte) (*RuleSet, error)`, `Evaluate(flags, gameTime) []WorldEvent`.
