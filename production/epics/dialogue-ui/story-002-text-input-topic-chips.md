## Acceptance Criteria

*From GDD `design/gdd/dialogue-ui.md`, scoped to this story:*

- [ ] **AC-1**: GIVEN an active conversation, WHEN the dialogue panel is in Active state, THEN a free-text input field is visible at the bottom of the panel, accepting keyboard input, with Enter key mapped to submit.
- [ ] **AC-2**: GIVEN topic suggestions available from the Question System, WHEN the dialogue panel is in Active state, THEN up to 6 topic suggestion chips are displayed in a horizontally scrollable row below the text input, rendered as clickable pen-and-ink icon chips.
- [ ] **AC-3**: GIVEN topic suggestion chips displayed, WHEN the player clicks a chip, THEN the chip's text fills the input field, replacing any existing input.
- [ ] **AC-4**: GIVEN the player submits a question (Enter or submit button), THEN the input field pulses amber, the chips hide, a quill scratch sound plays, the input is disabled, and the panel transitions to Processing state.
- [ ] **AC-5**: GIVEN the panel returns to Active state after an NPC response, THEN the input is re-enabled, cleared, and topic suggestion chips are refreshed with updated suggestions from the Question System.

## Implementation Notes

*Derived from ADR-0012:*

- **Text input element**: Use Kaiju's HTML/CSS-like text input. Style with Desk serif (Garamond class) font, 16px at reference resolution. Parchment-background field with umber border — no amber text on the parchment background (amber is accent/fill only per ADR-0012 forbidden rule).
- **Submit button**: Pen-and-ink quill icon (no skeuomorphic button). Positioned to the right of the input field. Enter key also submits — both must trigger the same submit flow.
- **Topic suggestion chips**: Rendered as a horizontal flex row below the input. Max 6 chips. If more than 6, horizontal scroll (overflow-x: auto or Kaiju equivalent). Each chip is a clickable element with pen-and-ink icon + short text label. Chip background: subtle parchment tone, distinguishable from the panel background.
- **Chip data source**: Chips are generated by the Question System (`topicSuggestions` from the question system's domain scoring + active threads + recent entities). Subscribe to the Question System's suggestion update events via EventBus. Chips update after each NPC response completes.
- **Chip click behaviour**: Clicking a chip copies its text into the input field (replace, not append). This is a UI-level action — no server round-trip.
- **Submit flow**: On submit (Enter or button click):
  1. Read input field text
  2. Play quill scratch audio (via Audio System event)
  3. Apply amber pulse animation to input field (CSS keyframe: brief amber border glow, 300ms)
  4. Hide chips
  5. Disable input
  6. Emit `QuestionSubmitted` event with the text → consumed by AI Dialogue Engine
  7. Panel transitions to Processing state (coordinated with Story 001's state machine)
- **Input re-enable**: When panel transitions from Response → Active (via Story 001's state machine), clear the input field and re-enable. Request fresh topic suggestions from Question System.
- **Accessibility**: Input field must be in the tab order. Chips must be navigable via arrow keys (left/right between chips, Enter to select). Focus ring on all interactive elements: oxblood/umber, ≥3:1 contrast.

## QA Test Cases

*Written by qa-lead at story creation. The developer implements against these — do not invent new test cases during implementation.*

- **AC-1** (free-text input in Active state):
  - Setup: Start conversation with any NPC, observe Active state
  - Verify: Text input visible at bottom of panel. Type characters → they appear. Press Enter → submit triggers.
  - Pass condition: Input accepts keyboard text, Enter submits, input is not visible in Hidden or Processing states

- **AC-2** (topic suggestion chips display):
  - Setup: Start conversation with an NPC who has knowledge domains (generates topic suggestions)
  - Verify: Up to 6 chips appear below the input field in a horizontal row. If more than 6, horizontal scrolling is available. Each chip shows a short text label.
  - Pass condition: Chips visible, correctly styled (pen-and-ink, not skeuomorphic), horizontally scrollable if >6

- **AC-3** (chip click fills input):
  - Setup: Active conversation with visible topic chips
  - Verify: Click a chip → input field fills with the chip's text. Click another chip → input field text is replaced (not appended).
  - Pass condition: Input reflects the clicked chip's text exactly, previous input replaced

- **AC-4** (submit flow — pulse, hide chips, disable, sound):
  - Setup: Type a question or click a chip, then press Enter
  - Verify: Input field briefly pulses amber (~300ms), chips disappear, input greys out (disabled), quill scratch sound plays, panel enters Processing state
  - Pass condition: All 5 effects (pulse, hide, disable, sound, state change) occur within the submit sequence

- **AC-5** (input reset and chip refresh after response):
  - Setup: Submit a question, wait for NPC response to complete (Response state → Active state)
  - Verify: Input field is cleared, enabled, and topic chips are refreshed (may differ from previous set if trust changed or new topics emerged)
  - Pass condition: Input ready for next question with updated chip suggestions
