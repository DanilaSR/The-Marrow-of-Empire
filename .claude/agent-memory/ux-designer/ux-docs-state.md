**Why:** the project's own standards (`design/CLAUDE.md` routing, accessibility checklist in the ux-designer agent spec) presume UX/accessibility docs that don't exist; camera decisions are being made without an accessibility floor.

**How to apply:** when asked for UX specs, accessibility requirements, or camera follow-ups, the gap is the deliverable. Art bible carries a related rule worth mirroring in camera/rendering: "Darkness never eats a decision" (Pillar 3) → occlusion handling should follow "a wall never eats a decision." Game positioning stresses Autonomy as a core player need and "treats the player like an adult" — camera-constraint designs (discrete zoom, camera locks) are in direct tension with that positioning; the no-auto-return decision is defensible but only if the compensation affordances (markers, recenter, onboarding) are fully built.
